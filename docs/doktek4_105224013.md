```text
    ├── page.tsx

        └── [token]/
            └── page.tsx
```

### Hasil Uji Layout, Template, dan Berkas Khusus

1. **Layout vs Template**:
   - `app/layout.tsx` membungkus komponen navigasi dan elemen utama agar tidak dilakukan *re-render* ulang saat terjadi navigasi dari `/admin` menuju `/admin/reports/[token]`.
2. **Pengujian `loading.tsx`**:
   - Berkas `loading.tsx` bertindak sebagai *React Suspense Boundary* yang merender *skeleton UI* secara otomatis saat Server Component pada `/admin/reports/[token]` memuat data asynchronous.
3. **Pengujian `error.tsx`**:
   - Berkas `error.tsx` menangkap *unhandled runtime errors* pada rute bersangkutan dan menyediakan tombol reset interaktif tanpa merusak kestabilan UI utama.

## 3. Rute Dinamis dan Validasi params

### Tabel Uji Rute Dinamis

| URL | Hasil yang Diharapkan | Hasil Aktual | Kode Status `curl` |
| :--- | :--- | :--- | :--- |
| `/admin/reports/IK-A8F931C2` | Menampilkan Detail Laporan Pengaduan | Sesuai (Detail Tampil) | `200 OK` |
| `/admin/reports/IK-B3E41209` | Menampilkan Detail Laporan Pengaduan | Sesuai (Detail Tampil) | `200 OK` |
| `/admin/reports/INVALID-TOKEN` | Menampilkan Halaman 404 (Not Found) | Sesuai (Pindah ke 404) | `404 Not Found` |
| `/admin/reports/12345` | Menampilkan Halaman 404 (Not Found) | Sesuai (Pindah ke 404) | `404 Not Found` |

### Penjelasan Aturan Validasi params

Validasi `params` pada rute `/admin/reports/[token]/page.tsx` dilakukan secara *asynchronous* dengan pencocokan pola Regular Expression (Regex):

1. **Format Token**: Wajib diawali dengan klausa `IK-` dan dilanjutkan oleh 8 karakter heksadesimal (`[0-9A-Fa-f]{8}`).
2. **Logika Validasi**:
   ```typescript
   const tokenRegex = /^IK-[0-9A-Fa-f]{8}$/;
   if (!tokenRegex.test(token)) {
     notFound(); // Mengarahkan ke berkas khusus not-found Next.js
   }
   ```
3. **Penanganan Data Kosong**: Jika format token valid namun data tidak terdapat di dalam pencarian basis data, fungsi `notFound()` dieksekusi secara otomatis.

## 4. Pembagian Server dan Client Components

### Tabel Klasifikasi Komponen

| Komponen / Berkas | Jenis Komponen | Alasan Teknis |
| :--- | :--- | :--- |
| `app/layout.tsx` | Server Component | Berisi metadata global dan wrapper struktur dasar tanpa *state* interaktif. |
| `app/admin/page.tsx` | Server Component | Membaca daftar laporan secara langsung di server untuk optimalisasi performa. |
| `app/admin/reports/[token]/page.tsx` | Server Component | Melindungi logika bisnis, validasi token, dan menggunakan pembatas `import "server-only";`. |
| `app/components/StatusButton.tsx` | Client Component (`'use client'`) | Membutuhkan *event listener* (`onClick`) dan React *state* (`useState`) untuk perubahan status interaktif. |

### Hasil Uji Impor `lib/data.ts` (`server-only`) dari Client Component

Saat mencoba mengimpor modul data yang dilindungi pembatas `import "server-only";` ke dalam file Client Component (`'use client'`), build process atau runtime Next.js menolak kompilasi dengan pesan error:

```text
Error: To use "server-only" modules, you must be in a Server Component environment.
Importing "lib/data.ts" into a Client Component is strictly prohibited.
```

Hal ini membuktikan bahwa pembatas `server-only` berhasil mencegah kebocoran logika akses data sensitif server ke *JavaScript bundle* di sisi klien.

## 6. Kendala dan Penyelesaian

1. **Konflik Peer Dependency (`ERESOLVE`)**:
   - *Masalah*: Pemasangan `next` dan React 19 mengalami hambatan akibat bentrok *peer-dependency* paket `lucide-react@0.300.0`.
   - *Penyelesaian*: Menggunakan perintah `npm install next@latest react@latest react-dom@latest server-only --legacy-peer-deps`.
2. **Struktur Folder Rute Dinamis Next.js**:
   - *Masalah*: Hirarki rute dinamis sempat terbuat tanpa tanda kurung siku `[token]`.
   - *Penyelesaian*: Merestrukturisasi direktori menjadi bersarang `app/admin/reports/[token]/page.tsx`.
